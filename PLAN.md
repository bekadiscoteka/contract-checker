# План доработки: Cognitive System + DSS («Проверь мой договор»)

Задание: `Final_Cognitive_System_DSS_EN.docx` (A — код 40, B — PDF 40, C — Streamlit 20).

**Продукт:** пользователь загружает один договор. Система находит рискованные пункты
и помогает решить, **что делать с договором**. Финальное решение принимает человек.

## Когнитивный цикл (один сценарий через все 7 этапов)

```
файл → T1 Perception → T2 Attention → T3 Memory → T4 Reasoning
     → T5 Decision (DSS) → T6 Action → T7 Learning ─┐
                     ↑______ обновлённые веса ______┘
```

| # | Модуль | Вход → выход | Метод | Что видно в UI |
|---|---|---|---|---|
| T1 | `perception.py` | файл → очищенные фрагменты + признаки | pdfplumber/docx/OCR, разбиение, regex: суммы, %, дни, сроки | число фрагментов, таблица признаков |
| T2 | `attention.py` | фрагменты → top-N важных с оценкой | ключевые слова × вес категории + сходство эмбеддингов, порог | ранжированный список, оценки внимания |
| T3 | `memory.py` | фрагмент → похожие пункты из прошлого + отзывы | SQLite (документы, находки, отзывы, решения) + поиск по эмбеддингам | «похожие пункты из прошлых проверок и как вы их оценили» |
| T4 | `reasoning.py` | фрагменты + признаки + память → риски с трассой вывода | правила (`risk_patterns.json` + числовые пороги), опционально LLM (Ollama) | для каждого риска цепочка «условие → правило → вывод» |
| T5 | `decision.py` | риски + параметры пользователя → рейтинг альтернатив | сценарная модель + TOPSIS (основная), WSM (для сравнения) | см. DSS |
| T6 | `action.py` | решение → внешний результат | HTML-отчёт (скачивание), запись решения в БД, опционально Telegram | кнопка «Скачать отчёт», журнал решений |
| T7 | `learning.py` | отзывы пользователя → новые веса и порог | мультипликативное обновление весов категорий, подстройка порога | веса до и после, один и тот же документ даёт другой результат |

`pipeline.py` соединяет модули по цепочке, у каждого dataclass на входе и выходе.

## DSS: «что делать с этим договором?»

**Альтернативы:** A1 подписать как есть · A2 подписать с правками · A3 отдать юристу · A4 отказаться.

**Данные из анализа:** баллы рисков `s_i` (low=1, medium=2, high=3), флаг «можно исправить
переговорами» по категории.
**Параметры пользователя:** ценность сделки V, стоимость юриста L, вероятность, что контрагент
примет правки p, эффективность юриста e, задержки в днях.

| Критерий | Тип | A1 | A2 | A3 | A4 |
|---|---|---|---|---|---|
| Остаточный риск | cost | Σs | Σs − p·Σs_fix | Σs·(1−e) | 0 |
| Затраты | cost | 0 | малые | L | 0 |
| Задержка, дни | cost | 0 | d_neg | d_law | 0 |
| Ожидаемая сохранённая ценность | benefit | V | V·(p + (1−p)·k) | ≈V | 0 |

- Веса критериев задаются слайдерами (D1). Используются TOPSIS и WSM (D2), опционально Monte Carlo по p.
- Ранжирование + одна явная рекомендация (D3).
- Объяснение: вклад каждого критерия, сравнение со вторым местом, конкретные пункты для правок (D4).
- What-if: слайдеры весов и параметров, рейтинг пересчитывается сразу; показывается, при каком весе меняется лидер (D5).
- Кнопка «Принять решение» записывает выбор человека в БД (T6/T7).
